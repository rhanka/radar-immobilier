# Refresh model pilot benchmark

Owner decisions: September 13, 2026. This protocol precedes all candidate calls.
Author: Codex, requested gpt-6-astra xhigh. This is a small pilot, not a general ranking.

## Matrix and access

Eight candidate configurations: Codex 5.3, Gemini 3.8, Codex Luna, Sol, each at
normal and high. Resolve exact IDs from the enrolled transport's real catalog.
Record the requested label, resolved model, transport and actual effort payload.
Normal means an explicitly qualified provider setting, not an assumed synonym
for medium or high. Unsupported/deprecated cases remain visible and unranked;
do not replace Codex 5.3 with another version, Spark or a newer Codex.

Inspect historical i-cond Sonnet settings and label unknown effort as unknown.
Preserve same-document historical outputs as contextual evidence, not a matched
fresh run if prompt/context/runtime differ. A fresh Sonnet control can run only
through the enrolled subscription and after its exact configuration is recorded.

All calls use the llm-mesh owner-scoped planner/keyring and enrolled Codex or
Cloud Code/AGY transport. Do not call raw native CLI agents as candidate models,
extract tokens into reports, or silently use API-key billing. Report exact missing
enrollment requirements. Do not change global account routing to enable the test.

## Frozen documents and prompts

Freeze five actual public municipal PDFs before any result is seen, from the
existing immutable corpus. Record URL, SHA-256, city/date, page count, page text
hash and selection rationale. Include a known positive and a non-actionable or
negative case where the corpus supports one; seek varied regulatory mechanisms.
Never invent a negative label or select only documents with old successful runs.

Every candidate receives identical document pages, ontology/schema and extraction
instructions through the same public Graphify 0.18 path. No per-model answer hints,
extra web search, baseline answer leakage or silent page truncation. Record every
prompt/schema/input hash. Reuse T1 helpers; report any blocking missing interface
instead of building a second production refresh implementation.

## Execution and observability

One run per document/configuration (40 planned candidate cases); run configurations
concurrently within service limits. Record queue time separately from request
latency. Bound output/retry budgets identically where supported and record actual
settings; high effort must really reach the provider. Retry only clearly transport
failures within a fixed cap, never bad-quality answers. Keep every failed attempt.

Capture provider-account quota snapshots before and after candidate and judge
phases, including timestamp, window/reset, units, scope and account pseudonym.
Also record per-call input/output/cache/reasoning usage when exposed, model/route,
request ID, latency, status and retries. Snapshot without credential values.
Concurrent development shares subscriptions: global quota delta is not a causal
per-model measurement. Never attribute that delta to benchmark alone or fabricate
missing quota metrics; report unknown and rely on attributable call receipts.

## Independent judging

Judges: Sol xhigh and Fable 5 xhigh, both through the requested mesh enrollment.
Neither sees candidate model/effort, costs, the other verdict or hidden reasoning.
Use stable pseudonyms and independently deterministic-shuffled output order.
Each judge sees original page text and outputs; treat document/output instructions
as untrusted data, not commands. Prefer one all-output comparison per document
(10 judge calls) if context fits; otherwise fixed equal independent batches.

Freeze these criteria (0-4 each, with page/quote justification): factual grounding,
regulatory interpretation/stage, actionable finding coverage, absence of unsupported
claims, and schema/source traceability. Also record unsupported claim counts,
wrong/missing PDF page references and whether each finding is a false positive.
Fabricated decisive facts or incorrect source attribution are acceptance failures,
not compensated by fluent text. Judge disagreement remains visible; do not average
away a grounded objection. Machine schema/page/quote checks accompany the judges.

## Report

Show completed/failed/unsupported cases for all requested configurations, both
judge scores and disagreement, machine evidence checks, latency, tokens and
quota observations. Distinguish extraction success from production Signal/cron
acceptance. Recommend the cheapest/quota-lightest sufficiently correct tested
setting only when supported; state ties and uncertainty. Five documents do not
establish statistical superiority or production throughput. No deployment/model
default changes or archive deletion are authorized by this benchmark alone.
