# Refresh 0.18 — executable continuation

Status: Astra design handoff, 2026-09-13; independent Gemini review pending. Build scope is NOT released. This continues i-cond's work; it is not a replacement architecture. Owner circuit: Astra design → Gemini 3.8 High → Sol xhigh → Gemini post-build; no two-host consensus claim.

## Numbered decisions

1. **Reuse the acquisition and CAS work.** Immo owns acquisition, parsing, interpretation, grounding, canonical publication, projection and Signal delivery. Geo supplies geometry/evidence only. Keep `worker-live.ts` and the existing S3 corpus/metadata. PR678 (`origin/feat/graphify-v23-cas-ingest`) supplies immutable manifests, content checksums, chunk/resume budgets, exclusions and merge semantics. Its reported 139 documents / 40 cities / 330 calls are candidate-only evidence, not publication or scheduled acceptance. The conductor reconciles that branch and identifies immutable artifacts; never edit i-cond's local run directories or rerun the old CLI to recreate them.

2. **Install the published contract, isolate the chat dependency.** Pin `@sentropic/graphify` to `0.18.0` (producer merge `1a723695d8a23ffe5e13f1988c52ded056f85c96`). Keep Immo chat's resolved mesh `0.1.2`. Unlike the older study's proposed encapsulation, released Graphify requires host-supplied planner/adapters. Add an explicitly named npm alias `@sentropic/llm-mesh-refresh: npm:@sentropic/llm-mesh@0.19.0` for that composition; imports use only its public root, `/facade` and, if required, `/node`. Lock Graphify's mesh resolution to the same 0.19.0 contract. No mesh types or instances cross into chat; no network mesh service, private `dist` imports, casts hiding version incompatibility, or opportunistic chat migration. Prove alias/type/runtime compatibility in the installed image before proceeding.

3. **Use the actual preparation + public profile/client composition.** `runConfiguredDataprep(root, {configPath, stateDir})` returns `profile`, `projectConfig`, `registries`, `registryExtraction`, `semanticDetection` and preparation artifacts; it does NOT extract. Materialize checked S3 inputs and stable original-document/page mappings in an ephemeral run directory. Reuse `radar/ontology/ontology-profile.yaml` and versioned registry data, with no workstation-relative paths. Use this public composition:

   - `createLlmMeshFacade({mode: 'cli', configResolver, keyring?})` from the alias `/facade`; stable workload `routingSubject {principalRef, ownerScopeRef}` supplied by Immo configuration, never inferred from credentials.
   - `GeminiAdapter({client: new CloudCodeRuntimeClient()})` and `OpenAIAdapter({client: new CodexRuntimeClient()})` from the alias root; one `createGraphifyMesh({routingSubject, adapters, createRoutePlanner: runtime => facade.createRoutePlanner(runtime)})` from `@sentropic/graphify/llm-mesh`. The enrolled planner carries acquired account auth; retain fail-closed resolver behavior, do not implement a second acquire/release loop.
   - `meshTextJsonClient(mesh, {provider: 'gemini', model: 'gemini-3.8-flash'})`; other capabilities/models explicit. Codex is a separately qualified route, not an implicit Gemini fallback. Graphify owns attempt completion, bounded account fallback and cancellation.
   - For each bounded text/page chunk, `buildProfileChunkPrompt({profile, projectConfig, registries}, {filePath, fileType, text})` from the Graphify root → `client.generateJson({schema, schemaDescription, prompt, maxOutputTokens, validateResponse})`. Use existing ontology property definitions as schema context, not a newly authored extraction prompt. `validateResponse` rejects invalid JSON, base/profile errors and ungrounded citations BEFORE route completion; repeat validation on the merged extraction.
   - The root exports `validateExtraction` and `validateProfileExtraction(extraction, {profile, registryExtraction})`. Accept only `status === 'completed'`, an existing output artifact and zero required-chunk failures. Read the client's parsed JSON output. `createDirectSemanticExtractionClient({textClient})` still builds a generic prompt; it is not the profile-aware shortcut. Do not use CLI/private helpers to fill this gap.

4. **Retain the complete city graph and evidence.** Port/reuse the existing v2.3 deterministic converters and PR678 merge/exclusion semantics as callable functions, preserving stable IDs and baseline nodes/edges. Feed `enrichGraphify34Snapshot` the assembled candidate directly. `emit-graphify34-candidates.ts` and `graphify-34-enrich.ts` demonstrate existing snapshot/apply contracts but consume PostgreSQL: calling either before projecting fresh data would enrich stale input. Check `graphifyGraphSchema`, complete Signal/source refs and existing property/source non-regression before publication. A generated path or a label used as description is not PDF evidence. Preserve `{docSha, original object key/sourceUrl, page, excerpt}` from actual bytes; verify quoted text on the cited original PDF page. Unknown regulatory facts stay absent/reviewable, never fabricated.

5. **Keep one guarded publisher and a resumable projection.** Persist immutable candidates + a manifest keyed by city, sorted input SHA set, parser/profile/registry/package/model-policy versions and exclusions. Read canonical bytes+ETag before deriving the candidate, archive via existing writer APIs, then use `writeCanonicalCityGraph` only (prefer the existing `applyGraphify34Snapshots` orchestration). `graph/<city>/latest.json` remains the complete `nodes`/`edges` snapshot, never a pointer. Reuse `upsertGraphAtomic` as the post-publication callback, including abort checks. Persist stage/hash receipts; retry after S3-success/PG-failure projects the same validated bytes without paying for extraction again. On canonical conflict, re-read/reconcile; never overwrite with a stale candidate. Count a city complete only after projection and acceptance. No global transaction is claimed.

6. **Make cron causally ordered.** Extend the existing 33/34 deployment basis with one refresh entrypoint sequencing acquisition → candidate/gates → canonical write → projection for selected cities. Keep acquisition S3-only (no provisional direct PG feed); return nonzero for any selected-city stage failure, required input/parse skip, exhausted budget or aborted projection. Do not infer success from the current worker's fleet error-rate threshold or from `project-graph-from-s3.ts` (GET/JSON/shape skips can exit zero). The separate legacy projection cron is suspended at cutover; ordering cannot depend on 03:17 versus 04:30. Use an immutable image digest, `concurrencyPolicy: Forbid`, deadlines/backoff/call/token caps and an exclusive durable refresh lock shared by scheduled/manual runs; Forbid alone does not fence manual Jobs or other writers. Candidate/checkpoint state lives in S3, local files are scratch.

7. **Credential refresh must survive pods.** Use a dedicated writable persistent keyring volume, seeded once from an out-of-band Secret under a single-writer lock; preserve refreshed state on all later starts. Never overwrite it from the bootstrap Secret per run. Keep ownership/permissions private, run as the existing non-root UID, restrict mounts to the refresh workload, and keep rotation/revocation controlled by the conductor. No credential values in Git, logs, artifacts or prompts. Secret→emptyDir is acceptable only for a disposable smoke and does not meet unattended acceptance. Storage class, at-rest protection, backup/restore and fencing are a conductor/poc-k8s readiness gate, not an infra mutation authorized by this design.

8. **Retire the parallel extraction path at cutover.** Remove `extractSemanticMentions`, its caller/config switch and obsolete tests; retire active `tools/graphify-v23` semantic/description CLI entrypoints and any direct shell publication route when the replacement is activated. Keep useful deterministic conversion/gate behavior in the new callable path. No catch-to-empty semantic success, CLI fallback or second canonical publisher remains. Small inert-code deletion commits may follow an initial disconnection, all before promotion.

## Acceptance ladder (no substitution between levels)

1. **Installed-package smoke:** Docker clean install of the exact release; CJS root + ESM `/llm-mesh`, declaration/type compatibility with the 0.19 alias, unchanged chat 0.1.2, bundled refresh entrypoint and profile/registries present. No provider call or typed Signal claim follows from this check.
2. **Consumer tests:** deterministic fixtures prove profiled prompt/client wiring, token cap, validation-before-success, owner isolation, all/one failed chunk, timeout/cancellation, retry budget reservation, input hash idempotence, CAS checksum mismatch, baseline/exclusion preservation, 3.4 enrichment and redaction. Real test S3/PG checks archive/CAS conflict, no premature publish, no regression, S3-success/PG-failure resume and skip-as-failure. Reuse existing writer/snapshot/enrichment suites.
3. **Real typed Signal/PDF:** conductor-run preprod, one known public PV PDF with one bounded chunk and a frozen oracle, real enrolled Gemini call. Assert a `Signal` of the expected regulatory kind with grounded instrument/stage/effect where actually stated, stable city/source/edge identity, exact original PDF SHA/page/excerpt and accessible PDF via the existing API/UI. Confirm the same candidate hash in full canonical JSON and PostgreSQL, then rerun without duplicate entities or new LLM calls. A generic nonempty graph, source-only output, fixture/stub or empty successful run fails this level. Expand to the reconciled 139-document batch only after this passes.
4. **Unattended schedule:** observe a CronJob-created Job (not only a manual Job), no workstation/tunnel dependency, ingest a newly eligible PV and verify its typed Signal/PDF. Observe another scheduled run after pod replacement and an actual credential refresh, proving durable rotated state and no duplicate charge/publication. Exercise bounded failure/resume and verify last complete graph remains recoverable. Preserve schedule/run UID, image digest, input/candidate/projection hashes, redacted refresh status and API evidence. Only conductor-controlled preprod acceptance permits gated production promotion.
