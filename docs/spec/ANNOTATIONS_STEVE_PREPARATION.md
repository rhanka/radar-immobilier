# Steve source preparation against M1

This is immo-owned IM-1/IM-2 preparation on synthetic inputs, independent of any
UI. It does not claim a real Google read, canonical import, or corpus completion.
The reference remains private SPEC v4/X3 and the raw owner D1–D4 decisions.

## Workbook path

1. `captureSyntheticGoogleWorkbook` reads a fixture in the Google Sheets API
   response format, including native tab IDs, grid offsets, typed input/effective
   values, formulas, notes and hidden row/column/sheet metadata. It retains the
   complete original UTF-8 response, including fields it does not interpret.
2. Feedback cell mappings and documentary attribution are explicit inputs.
   Numeric/formula cells remain source resources. Exact text cells become
   separate homogeneous contributions; no account is inferred from a name.
3. `inventorySyntheticWorkbook` freezes source and capture digests, version-local
   workbook/sheet/row/cell resources and source locators. Missing expected tabs,
   attachments and unqualified coverage are visible issues. Row numbers never
   imply stable identity between versions. Resources must be assigned before use.
4. `prepareSyntheticWorkbook` calls `prepareSyntheticSourceUnit` for every
   contribution. Shared constructors produce a discussion structure and root
   comment with exact text, provenance, structure pin and historical version gap.
   Same-row human/assistant contributions share a source resource and retain
   separate authorship. A retry with frozen execution/registration inputs is identical.
5. The output contains candidates, one common M1 import manifest and separate
   prepared/blocked counts. Its status is `prepared-not-committed`; no service,
   receipt, review, SQL content store or AI dispatch is substituted by immo.

Sheets responses do not establish Drive comment/attachment completeness. Those
features remain explicitly unavailable in the fixture reader. The production
collector must qualify a full field/range request, all tabs and hidden elements,
Drive sidecars, analysis pieces and the exact source manifest. It must preserve
formula/effective-value precision and original bytes. This remains **immo work**.

## Map category dispositions

`planSteveMapCategory` records the reference mappings as preparation only:

| Source category | Destination / unresolved evidence |
|---|---|
| Lot note | Common discussion on a qualified lot or historical source |
| Manual pin | Position resource with coordinates/CRS/units/precision; title/category/text in the common annotation/profile |
| Manual zone | Match the authoritative zonage resource; explicit version link, no second zonage reference |
| Listing | Qualify the business/source mapping and all price/URL fields; no annotation replacement |
| `favori`, `sollicite`, `lettre`, `envente` mark | Existing prospect dimensions/status proposals; documentary attribution and authorized projection still required |
| `verifie` or unknown mark | Unresolved meaning/equivalence; no review or invented status |
| Unknown category | Explicit inventory/disposition required; never silently omitted |

No projection writes `prospect_marks` or invents `author_id`. Exact map-export
parsing, authoritative zone/listing matching, actual position evidence and linked
corrections remain immo integration work to qualify against the supplied sources.

## Entry into real data

The current entrypoints refuse a non-synthetic classification. Real sources require
Farid D5/D6 and pre-hash redaction, proven assignments and Q4 dispositions. Legacy
deleted notes never enter these captures or manifests; only their aggregate count
may appear in the retirement result. A real-data rehearsal has the same gates.

M2/M3 must deliver the cluster-mesh runtime, a usable payload/import interface,
typed complete result receipts and exact authorized readback. M1's digest-only
unit DTO and minimal receipt cannot establish durable import success. Any added
shared signature/schema re-enters the freeze change protocol before consumption.
Immo then qualifies integrated synthetic import/retry/readback, backing/lifecycle,
conversion and deployment/restore operations before the authorized real window.
