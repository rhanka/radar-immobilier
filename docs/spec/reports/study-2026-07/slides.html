Grilles d'évaluation

Preuve d'abord, pas résumé

Conserver le moteur OCR spécialisé (Mistral OCR 4) sur les documents complexes.

Prudence sur la complétion (completion Mistral) : mesurer et borner l'écart d'erreur avant tout usage réglementaire.

  • Une grille reconstruite peut être plausible et fausse sur une valeur critique (hauteur, densité, usage).
  • Liens de grille hétérogènes et non lus : LienGrille, URL_GRILLE, GRILLE_URL.
  • Cible : extraction structurée avec preuve — cellule, page, citation, table, champ.

Lots & PII

Cadastre exploitable, sans propriétaire

  • Aucun propriétaire exposé ; propriétés client limitées à noLot + citySlug.

  • Couche la plus industrialisable (~1103 collections) ; risque = volumétrie, mémoire, pagination, fréquence.

Architecture

Modulaire & réversible

sources → acquisition/scraping → OCR/extraction/graphify → graphe + citations → PostgreSQL/PostGIS → API domaine → UI → intégrations

  • Monorepo : API, UI, bibliothèques de domaine, jobs.
  • Sources pilotées par configuration, un scraper générique.
  • Fournisseurs OCR / LLM interchangeables ; projection rejouable.
  • Couche d'identité OAuth réversible sans toucher au domaine.
  • Villes « dures » documentées (anti-bot, sites sans PDF, périmètres non résolus).
  • Preuve PDF : archive objet sondée d'abord, repli sur store de métadonnées.

Exploitation & coûts

Industrialiser sans sur-vendre

Coût au siège

Runs ciblés, focus 30, premium sur les cas durs. Coût d'une preuve, maîtrisé.

Coût complet

1104 villes, refresh, OCR, stockage, LLM, supervision. Coût d'un service, dominé par les volumes récurrents.

  • Premium réservé aux cas à forte valeur ; transformations déterministes ailleurs.
  • Batcher les villes, borner les extractions, jobs incrémentaux (hashes, fraîcheur).
  • Unité économique = signal vérifiable produit, pas le token brut.
  • CronJobs de refresh suspendus (FinOps) : job défaillant réveillait un pool de calcul → suspend:true jusqu'au fix.
