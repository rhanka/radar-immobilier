Work starts at immo `ea90951c` in `feat/annotations-host`. The reference inputs are
`SPEC-INJECTION-IMMO-v4.md` (41bc34b5…) and `EXIGENCES_IMMO_v3.md` (9a1e9095…),

## Decisions

- D1: Consume the exact shared M1 contract, never copy its types, hash algorithms,
  revision builders, command processing, or durable store into immo.
- D2: Immo owns explicit tenant/workspace assignments, membership/capabilities,
  source resource identities and version evidence. No default scope or admin bypass.
  Resource identities encode municipality, native kind and native ID; display
  `gn-…` IDs and legacy signal UUIDs never become graph identities by inference.
- D3: Inject `CanonicalHttpPorts` and `CanonicalRouterFactory<Hono>` from the
  cluster-mesh module. Missing module or authentication denies access. M1 declares
  the factory but does not implement the durable store or canonical router (M2/M3).
  Development and synthetic qualification continue against declared seams.
- D4: The host resolver never substitutes a current version for historical evidence.
  Membership/account revocation denies every target; full multi-target access is
  required. Unknown or ambiguous resources cannot authorize revision review.
- D5: Prepare Steve imports using shared builders, faithful bodies and explicit
  documentary attribution/source time. No live source access or real inscription
  before Farid D5/D6 and proven assignments. No UI dependency or AI call on save.
- D6: Remove legacy routes, services, domain contracts, UI clients/components,
  counters, badges, notes scopes and their tests. Marks and contacts remain usable.
  Historical SQL remains immutable; new guarded retirement refuses active notes
  until a verified canonical conversion. Deleted notes have aggregate counts only.
- D8: Ordinary migration is schema-only. Manual 0009 adoption requires explicit
  operator-reference/catalog qualification; destructive retirement requires a
  closed-window reference and verified host catalog/receipt. Fenced promotion,
  suspended ordinary restore and forward recovery precede real adoption.
- D7: No live database, deployment, root UAT checkout or restore is changed here.
  The operational plan closes old replicas/SSE buffers and incompatible restores.
  Existing backups expire normally; no new copy of notes is created.

## Qualification

- Synthetic membership/revocation, explicit grants, cross-scope and multi-target
  denials; resource versions, native identity collisions and geographic digests.
- Shared M1 hash vectors and revision builders; exact package/source provenance.
- Hono composition with injected module seam, authentication, absent-module denial.
- Import preparation preserves complete text, mixed attribution and unknown dates;
  no canonical write on missing decisions or unresolved resource evidence.
- Legacy endpoints disappear, UI no longer fetches notes, marks tests remain green.
- Fresh database migration and guarded upgrade/retirement; immutable SQL checksums,
  0009 gap and non-monotone journal recognized rather than silently skipped.

## Independent design reconciliation

Two blind read-only reviews covered contract correctness and eradication/security.
Both permit synthetic host work and require M2/M3 before operational conversion.

- Accepted: M1 resolver has no source-version argument. Immo uses explicitly
  version-specific snapshot IDs and separately verifies source indicators. A new
  snapshot is a new primary resource; moving to it needs the common linked
  conversion, never an in-place annotation retargeting.
- Accepted: bind capability/resolver calls to the authenticated OIDC subject and
  require an existing approved account. M1 does not specify an authentication
  context key; its real router must qualify this boundary at M3.
- Accepted: schema installation and destructive retirement are separate phases
  under one migration/cutover lock. No active-note retirement is enabled by M1:
  the declared import DTO lacks a payload channel and its unit receipts do not
  yet enumerate the canonical results required for reconciliation.
- Accepted: freeze technical registration/execution inputs during preparation,
  validate source indicators explicitly, and never equate synthetic builder
  output with durable import success or receipt completeness.
- Accepted: qualify all migration predecessors and checksums, including 0009,
  and remove the lot marks/notes Promise.all before removing the notes endpoint.
